# 方案与工程取舍

## 模型有选择权，工具有最终执行权

`HTTPPlanner.choose` 通过 Chat Completions 的 tools 发出原生 function calling 请求。每轮提供受信执行器状态，模型选择一个动作。`SchedulingAgent.run` 校验工具名和参数，调用实际工具，把结果作为 role=tool 消息送回模型。模型可以选择补查、重新查询、请求资料、请求确认、阻断、保存或结束。模型不直接写数据库，不生成最终成功字段。

默认 `OfflinePlanner` 是可复现的规则测试替身；它只能证明流程和守卫，不是 ReAct 能力证据。真实证据在 `examples/live/`，`mode=live_model`。不依赖 LangGraph 等框架，用标准库让评审能直接看完整循环和边界。

## 主要模块

| 模块 | 职责 |
|---|---|
| domain.py | 请求字段、日期/时间和精确确认绑定 |
| planner.py | 模型工具 schema、HTTP 协议、错误处理、离线替身 |
| tools.py | 素材读取、补查、审核、查询、确认、保存前守卫 |
| storage.py | SQLite 事务、唯一约束、幂等与草稿预留 |
| agent.py | 有限循环、Trace、工具错误观察、可信结果投影 |
| cli.py | 单项/批量请求、退出码、输出持久化 |

## 审核与补查

规则文件有版本号、必填字段、阻断标签和人工复核标签。补查只从可信本地补充库填充缺失字段，不能覆盖已有风险标签。补查改变资料后必须重新审核；补查无新资料则保留既有缺失证据，允许直接请求补充。保存前重新读取素材和规则，避免审核后数据变化被忽略。

当前规则是可解释的合成业务规则，不检测真实图像、视频、音频或文本事实。元数据本身若被错误标注，规则无法发现语义风险。

## 确认边界

proposal_id 对 request_id、素材、原时间、日期、渠道、时区和建议时间做确定性摘要。工具只读原始用户 approval，模型的工具参数没有授权字段。某个时段的确认不能用于另一时段或另一请求。原要求不被覆盖，实际保存时间单独存 scheduled_time。

CLI 是可信操作者边界；摘要不是密码学身份凭证。生产场景应由认证用户签署审批事件，记录审批人、过期时间和版本。已有草稿的精确审批会存入数据库，重放原请求时可复用原审批，但不能移用到新时段。

## 幂等、冲突、事务

1. request_id 唯一；原请求 fingerprint 不变才可幂等复用。
2. `(material_id,date,channel)` 唯一，换 ID 不能给同一素材同天同渠道再建草稿。
3. `(date,channel,scheduled_time)` 唯一，防止两个素材占同一位置。
4. `BEGIN IMMEDIATE` 获取写事务后复检；检查占用、INSERT、COMMIT 处于同一 SQLite 事务。
5. INSERT 后注入失败可验证回滚。没有 commit 成功就不返回 saved。

草稿会预留本数据库时段。相同请求重试仍查询最新外部占用；已存草稿冲突返回 existing_conflict，保留旧草稿、提示人工处理。没有自动取消、覆盖或重排接口。

外部排期文件不是事务数据库，本地查询后仍存在跨系统 TOCTOU 窗口；保存前重读只能缩小窗口，不能提供跨进程文件更新的线性一致性。生产必须把权威排期纳入事务或使用版本号 compare-and-set。

## 故障与预算

最多 12 步，CLI 允许 1–50 步。HTTP 每调用超时 45 秒，不隐式无限重试。超限返回 incomplete；若最后一步已 commit，仍保留 saved 事实，避免把已落盘副作用隐藏成“未保存”。模型错误与工具错误分开返回，live 不自动退回 offline。

只接受一次一个工具调用；拒绝自由文本成功、未知工具、额外参数和格式错误。没有 publish 工具；最终 published 恒为 false。Trace 记录简短可核查理由，不记录模型内部思考或 API 密钥。
