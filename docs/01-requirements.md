# 需求与成功标准

## 用户、痛点、目标

内容运营提供素材 ID、元数据、硬性发布时间与当前占用。系统找出可处理素材和阻碍，给出可确认、无内部冲突的草稿排期。不能越权改动硬性要求，更不能声称真实发布。

## 输入契约

- `request_id`：调用方稳定业务请求 ID；重复调用保持不变。
- `material_id`：素材库 ID；标识符只允许字母、数字、下划线、连字符。
- `date` / `required_time`：有效 ISO 日期和 24 小时制 HH:MM；当前均为硬性要求。
- `channel`：默认 main；`timezone`：仅支持 Asia/Shanghai。
- `approval`：可选，必须包含绑定本请求和替代时段的 `proposal_id` 与 `approved_time`。不接受泛化的 `confirmed=true`。

素材需要标题、类型、版权状态、敏感标签与 ready 状态。缺失素材字段与非法用户请求分开处理。日期是业务输入，不隐式使用系统当天日期。

## 必验收点

| 场景 | 成功标准 |
|---|---|
| 正常排期 | 审核通过、原要求时段可用，草稿落盘，published=false |
| 信息缺失 | 先补查，无法补齐则明确待补充，不保存 |
| 规则风险 | 高风险阻断；需人工审核的风险等待复核；时段同意不解除审核风险 |
| 时段冲突 | 建议具体可用替代时段；原要求保留；未确认不保存 |
| 重复提交 | 同一请求返回同一 draft_id、仅一行；相同 ID 改原始载荷报错 |
| 保存失败 | 明确 failed；事务回滚；不能虚报成功 |

额外验证：更换占用时段重新运行、旧确认失效、已存草稿后续冲突、补查恢复、无可用时段、并发、提示注入、模型格式错误、步数上限。

## 范围

CLI 单条/批量请求，SQLite 单机持久化，离线替身与真实模型接口。业务工具采用本地文件和 SQLite，符合题目允许 Mock 业务工具的约束。没有前端、真实发布、生产审核引擎和部署平台。

题目材料未给数字题号，提交时以“素材审核与发布排期 Agent”为题名，实际题号由候选人根据试卷填写。
